# S4：codegraph 能否作为库接入，API 稳定性

> 状态：**已实测**（问题 / 方法 / 判定标准在实测前预登记，实测后未修改判定标准）
> 对应架构：§0（codegraph 档位 B：v1 只做 TS/JS）、§5（Structure 层）、
> §13（许可证）、执行计划 S4。
> 日期：2026-11-18

## 1. 问题

1. `@colbymchenry/codegraph` 是否以**公开 npm 包**形式提供可嵌入的库 API？
   公开版本、发版节奏、维护状态如何？
2. 其 Library Usage 文档承诺的 API（`init/open/indexAll/searchNodes/getCallers/
   buildContext/getImpactRadius/watch/unwatch/close`）是否与实际包行为一致？
3. 版本耦合有多强：`engines`、Node 版本要求、对 `web-tree-sitter`/`tree-sitter-wasms`
   的依赖范围、是否依赖按平台分发的原生包？
4. 许可证是否允许参考/复用（MIT）？是否必须读源码才能接入（本 Spike 禁止读源码）？
5. 若不可接入，退回自写最小 L0/L1 的代价是否可接受？

## 2. 方法（实测前预登记）

**只读边界（硬约束）**

- 本地参考仓库 `<home>\ZCodeProject\_research\codegraph` 只读以下内容：
  `README.md`、`package.json`、`LICENSE`；不读 `src/`、`scripts/`、`__tests__/`、
  `codegraph-kernel/`，不运行该仓库任何脚本、不 `npm install` 该仓库、不执行其 CLI。
- **绝对不读取 obelisk 源码**（§13 / 执行规则 8）。
- 公开信息只走 npm registry / npmjs 页面 / GitHub Releases 等公开渠道（WebFetch 或
  `npm view`），不下载源码包解压阅读。

**公开版本与稳定性调查**

1. `npm view @colbymchenry/codegraph version dist-tags time engines dependencies
   optionalDependencies license repository` ——记录原始输出。
2. 取 npm registry packument（`https://registry.npmjs.org/@colbymchenry%2Fcodegraph`）
   的 `versions` 列表与 `time`，统计版本数、首末版本、最近发布时间、
   major/minor 递增节奏；从版本号变化推断是否有 breaking 迹象（仅凭 semver 与时间，
   不读 changelog 源码；若公开 CHANGELOG 可读则只读公开文本）。
3. WebFetch npmjs 包页面 / GitHub Releases，确认维护活跃度与公开 API 文档是否有变化。

**最小实测（允许，≤50 行，按公开文档）**

- 在**仓库外的临时空目录**（`%TEMP%\ano-s4-*`）安装该包，
  使用 `npm install --ignore-scripts` 避免执行其生命周期脚本；
  若包在 `--ignore-scripts` 下缺少按平台分发的二进制而无法运行，如实记录，
  不改用执行安装脚本的方式强行跑（除非确认无 postinstall 风险且用户允许）。
- 脚本放**另一个目录**（`scripts/spikes/s4-codegraph.mjs`），通过参数接收 fixture 路径，
  不进入被安装包目录内运行。
- fixture：在临时目录生成一个 20 文件左右的 TS/JS 小项目（自造），
  逐个调用文档中的 API，记录成功/失败、错误原文、耗时、`node:sqlite` 可用性。
- 全程记录实际版本号，不锁定/不修改根 `package.json` 与 `scripts/package.json`。

## 3. 判定标准（实测前预登记，事后不改）

| # | 判据 | 通过条件 |
|---|---|---|
| P1 | 公开可获取 | npm 上存在该包，能查到版本、许可证、仓库地址；readme 含 Library Usage 章节 |
| P2 | 文档 API 可调用 | ≤50 行脚本在自造 fixture 上成功完成至少 `init`（或 `open`）+ `indexAll` + 1 个查询（`searchNodes`/`getCallers`/`getImpactRadius` 之一） |
| P3 | 版本耦合已量化 | 记录确切版本、Node 要求、依赖范围、按平台分发方式、发版节奏；给出"升级是否会破坏接入"的判断依据（semver + 公开发布记录） |
| P4 | 许可证 | MIT 或等价宽松许可，允许参考；若为 copyleft 则记录并升级为决策门 |
| P5 | 无源码依赖 | 接入过程不需要读其 `src/` 或运行其脚本；仅凭 README + 包入口即可工作 |

- **失败备选**（架构既定）：自写最小 L0/L1（P1 默认路线）。S4 的结论只决定
  "是否把 codegraph 作为可选后端/参考实现"，不改变 ANO 自写主路线。

嵌入要求（来自公开 README，实测验证）：

- `npm i @colbymchenry/codegraph` 会自动拉取当前平台的配套包（本例 win32-x64）；

## 5. 最小脚本实测（实测）

- 安装目录：`D:/Temp/ano-s4-pkg`（仓库外空目录），命令
  `npm install --ignore-scripts --no-audit --no-fund @colbymchenry/codegraph@1.6.3`，
  输出 `added 2 packages in 4s`。**未执行其任何生命周期脚本**。
- 输入：`D:/Temp/ano-s4-fixture`，自造 **20 个 TS/JS 文件**（service/api/util 三层的调用链）。
- 脚本：`scripts/spikes/s4-codegraph.mjs`，**46 行**（上限 50 行），只 import 公开入口，
  不读包源码；通过参数接收安装目录与项目路径。

| 文档 API | 结果 | 耗时 | 实际返回（摘要） |
|---|---|---|---|
| `CodeGraph.init(project)` | ✅ | 182.1 ms | 实例；`backend: node-sqlite`、`fts5Available: true`、db 在 `.codegraph/codegraph.db` |
| `indexAll({onProgress})` | ✅ | 415.5 ms | `success:true`，20 文件索引、0 跳过/0 错误、**76 节点 / 128 边**、`durationMs:414` |
| `searchNodes('UserService')` | ✅ | 4.1 ms | 命中 class 节点 `UserService`（`src/services/user-service.ts:3-12`） |
| `getCallers(id)` | ✅ | 0.8 ms | 返回调用方节点数组（含 `src/index.ts` 等） |
| `getImpactRadius(id, 2)` | ✅ | 1.1 ms | 返回 `{nodes, edges}`，边含 `contains` / `calls` |
| `buildContext('fix login bug', {maxNodes:20, includeCode:true, format:'markdown'})` | ✅ | 13.4 ms | Markdown；Entry Points 列出 `login`、`POSTLogin` |
| `watch()` / `unwatch()` | ✅ | 77.4 / 0.2 ms | 仅验证启动/停止，未验证文件变更反应 |
| `close()` | ✅ | 0.9 ms | 正常关闭 |

`onProgress` 共收到 **102 条**事件（scanning → parsing → linking，最后 `linking 55/55`）。

**CommonJS 接入（README 明确给出的另一种写法）实测通过**：

```
const { CodeGraph } = require('@colbymchenry/codegraph');
// cjs CodeGraph type: function init: function open: function
// CodeGraph.open(fixture) -> ok; searchNodes -> 7 hits; close -> ok
```

**ESM 默认导入与 README 不一致（重要）**：在本机 Node 24.14.0 原生 ESM 下，
`import CodeGraph from '@colbymchenry/codegraph'` 得到的 default 是**对象而不是类**
（对象上有 41 个键，`CodeGraph` 类在 `default.CodeGraph`）。脚本因此拒绝直接调用并记录
`default export is object, not a constructor`（对象上没有 `init` 方法）。
README 的 ESM 示例不能照抄；CJS 解构写法可用。
（原因未追查：追查需读包源码，超出本 Spike 边界。）

## 6. 结论

| 判据 | 结果 | 依据 |
|---|---|---|
| P1 公开可获取 | **通过** | npm 1.6.3、MIT、仓库地址、发布版 README 第 613 行含 Library Usage |
| P2 文档 API 可调用 | **通过** | 46 行脚本完成 init/open + indexAll + 5 类查询/上下文 + watch/close，全部成功 |
| P3 版本耦合已量化 | **通过** | 精确 1.6.3；平台包精确锁版本；49 版 / 1.x 19 版 / 平均 8.3 天；无 `engines` 但 README 要求 Node 22.5+；平台包 270 MB |
| P4 许可证 | **通过** | MIT（shim 与平台包） |
| P5 无源码依赖 | **通过** | 只读 README/package.json/LICENSE；公开入口黑盒调用；未运行仓库脚本 |

**判定：codegraph 可以作为库接入（Windows x64 + Node 24.14 实测），但版本耦合偏高，
且 README 的 ESM 示例与运行时不符。**

对架构的结论（S4 只决定"是否作为可选后端/参考实现"）：
1. **维持自写最小 L0/L1 作为 P1 主路线**（架构既定），codegraph 不作核心依赖；
2. 若用作对照/可选后端：**锁定精确版本 1.6.3**，用 CJS 或 `default.CodeGraph` 导入，
   预算约 263 MB 安装体积与 Node ≥22.5，并接受每 8 天左右一次发版带来的漂移；
3. 平台包与 shim 精确同版本绑定，升级必须整体升级，不能只升 shim；
4. 无 `engines` 字段意味着 npm 不会拦截不兼容 Node；需在 ANO 侧自行检查版本。

## 7. 限制

- 只测 `@colbymchenry/codegraph@1.6.3`、win32-x64、Node 24.14.0；未测 Node 22、Linux/macOS、arm64。
- **GitHub Releases 不可达**，未读 release notes/changelog；"API 稳定性"只能由 npm 发版时间、
  semver 与一次运行探针推断，不能证明未来不破坏。
- 只测一个版本，未做跨版本兼容性矩阵（如 1.5.x → 1.6.3）。
- fixture 只有 20 个自造文件；不覆盖大仓库、增量索引、内存、索引质量/召回率。
  `searchNodes` 命中 7 条、`getCallers` 返回文件节点等现象只记录，不作质量结论。
- `watch()` 只测启动/停止，未测真实文件变更同步。
- `--ignore-scripts` 安装；其他平台是否依赖生命周期脚本未验证。
- 安装 4 秒使用了本机 npm 缓存，不是网络下载基准。
- ESM/CJS 导出形状差异是运行时观测（原生 ESM）；根因未查（读包源码超出 S4 边界）。
- 本地参考仓库与 npm 包均为 1.6.3，但本地仓库可能包含未发布改动，未逐文件比对。
